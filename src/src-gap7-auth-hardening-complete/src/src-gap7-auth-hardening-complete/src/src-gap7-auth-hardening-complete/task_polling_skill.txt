// Engineer Task Polling Skill Documentation and Implementation Pattern
// 
// SKILL: Autonomous Task Polling and Execution Loop
// VERSION: 1.0
// CREATED: 2026-08-09
// AUTHOR: Engineer Agent
//
// PURPOSE:
// Enable Engineer agent to autonomously work through a task queue by:
// 1. Checking frank_tasks table for PENDING tasks
// 2. Selecting the highest-priority task with satisfied dependencies
// 3. Marking it IN_PROGRESS and executing
// 4. Updating status to COMPLETE or BLOCKED based on outcome
// 5. Repeating until no eligible tasks remain
//
// ARCHITECTURE:
//
// Task Polling Loop (task_polling.rs)
// ├─ poll_tasks_autonomous()          — Main entry point, orchestrates loop
// ├─ find_next_eligible_task()        — Queries & selects by priority + deps
// ├─ check_dependencies_satisfied()   — Validates all deps are COMPLETE
// ├─ mark_task_in_progress()          — Updates status, sets started_at
// ├─ execute_task()                   — Executes the task logic
// ├─ update_task_status()             — Marks COMPLETE or BLOCKED
// └─ get_polling_stats()              — Reports queue statistics
//
// Integration Points (task_polling_tools.rs)
// ├─ poll_tasks()                     — Tool wrapper for agent use
// └─ get_task_stats()                 — Tool wrapper for statistics
//
// DATABASE SCHEMA (frank_tasks):
//
// ┌──────────────────────────────────────────────────────────────────────┐
// │ task_id (UUID PK)           │ Unique task identifier                 │
// ├──────────────────────────────────────────────────────────────────────┤
// │ title (TEXT)                │ Task name                              │
// │ description (TEXT)          │ Task details                           │
// │ status (TEXT)               │ PENDING|ASSIGNED|IN_PROGRESS|etc       │
// │ priority (INT, 1-10)        │ Higher = more urgent                   │
// │ assigned_to (TEXT)          │ Agent name or NULL                     │
// ├──────────────────────────────────────────────────────────────────────┤
// │ dependencies (UUID[])       │ Array of task_id that must complete    │
// │ tags (TEXT[])               │ Metadata for filtering                 │
// │ context (JSONB)             │ Task-specific execution parameters     │
// ├──────────────────────────────────────────────────────────────────────┤
// │ created_at (TIMESTAMPTZ)    │ When task was created                  │
// │ updated_at (TIMESTAMPTZ)    │ Auto-updated on each modification      │
// │ started_at (TIMESTAMPTZ)    │ When task moved to IN_PROGRESS         │
// │ completed_at (TIMESTAMPTZ)  │ When task moved to COMPLETE            │
// └──────────────────────────────────────────────────────────────────────┘
//
// DEPENDENCY RESOLUTION ALGORITHM:
//
// For each PENDING task in priority order:
//   1. Check if dependencies array is empty
//      → If yes: eligible, select it (highest priority wins)
//      → If no: continue to step 2
//   2. Query: SELECT COUNT(*) FROM frank_tasks 
//            WHERE task_id = ANY($1) AND status != 'COMPLETE'
//   3. If count = 0: all dependencies complete → eligible
//   4. If count > 0: dependencies incomplete → skip, try next
//   5. Repeat until eligible task found or no more tasks
//
// EXECUTION FLOW:
//
// Iteration 1:
//   ↓
// find_next_eligible_task() ← query PENDING tasks, priority DESC
//   ↓
// Found? → YES ↓ NO → Break loop, return results
//   ↓
// mark_task_in_progress() ← UPDATE status, set started_at
//   ↓
// execute_task() ← Extract context, run task logic
//   ↓
// Success? → YES: status = COMPLETE ↓ NO: status = BLOCKED
//   ↓
// update_task_status() ← UPDATE status, set completed_at (if COMPLETE)
//   ↓
// Record result in results vector
//   ↓
// Continue to next iteration →
//
// USAGE FROM AGENT:
//
// Engineer spawns with goal: \"Poll and execute all pending tasks\"
// 
// Agent workflow:
// 1. Call poll_tasks() tool with empty input {}
// 2. Tool invokes task_polling::poll_tasks_autonomous()
// 3. Autonomous loop runs to completion
// 4. Returns TaskPollingResult vector with outcomes
// 5. Agent summarizes and reports to SuperFrank
//
// EXAMPLE TASK STRUCTURE:
//
// {
//   \"task_id\": \"f74bd8c8-a4ba-4305-a3a9-946f6f332862\",\n//   \"title\": \"Build auth module\",\n//   \"description\": \"Implement OAuth2 flow\",\n//   \"status\": \"PENDING\",\n//   \"priority\": 9,\n//   \"assigned_to\": \"Engineer\",\n//   \"dependencies\": [\"dep-id-1\", \"dep-id-2\"],\n//   \"tags\": [\"auth\", \"critical\"],\n//   \"context\": {\n//     \"action\": \"build\",\n//     \"module\": \"auth\",\n//     \"config_path\": \"/opt/frankos/config/auth.yaml\"\n//   },\n//   \"created_at\": \"2026-08-09T10:00:00Z\",\n//   \"updated_at\": \"2026-08-09T10:00:00Z\",\n//   \"started_at\": null,\n//   \"completed_at\": null\n// }\n//\n// ERROR HANDLING:\n//\n// - Dependency check failure → Log warning, skip to next task\n// - Task execution failure → Mark BLOCKED with error reason\n// - DB query failure → Break loop, return partial results\n// - Max iterations reached → Safety limit (100), halt gracefully\n//\n// QUERY PATTERNS:\n//\n// Find next task (atomic, priority-ordered):\n//   SELECT ... FROM frank_tasks WHERE status = 'PENDING'\n//   ORDER BY priority DESC, created_at ASC LIMIT 50\n//\n// Check dependencies satisfied (all must be COMPLETE):\n//   SELECT COUNT(*) FROM frank_tasks \n//   WHERE task_id = ANY($1) AND status != 'COMPLETE'\n//\n// Update status (with auto-timestamp):\n//   UPDATE frank_tasks SET status = $2, updated_at = NOW(), ...\n//   WHERE task_id = $1\n//\n// Get statistics:\n//   SELECT COUNT(*) FILTER (WHERE status = ...) as status_name\n//   FROM frank_tasks\n//\n// PERFORMANCE CONSIDERATIONS:\n//\n// - Indexed on: status, assigned_to, priority\n// - Limit 50 candidates per iteration (prevents full table scan)\n// - Dependency check is O(n) where n = # of deps (typically 1-3)\n// - Update operations use indexed task_id PK\n// - Loop terminates quickly if no eligible tasks\n//\n// FUTURE ENHANCEMENTS:\n//\n// 1.
